# 预注册：Jev 作为福滤娃识别层的离线评测

> **冻结时间**：2026-09-19（在跑任何一次 Jev 判定之前写完）
> **纪律来源**：jev 套利项目的 E11 / E14 两次预注册 —— **先钉死判据再抓数据**，
> 跑完只许如实报告，不许改了阈值再报。

---

## 一、要回答的问题

原版福滤娃的识别层只有三样东西：社区名单（净票≥3）、778 条关键词、SimHash 话术指纹。
roadmap 里挂了四个月的 "AI 识别（Optional AI）" 始终没做，`DetectionSource` 类型里
留了 `'ai'` 却永远没产出过一条判定。

**本次评测只回答一个问题：把账号档案交给 Jev，它能不能在"宁可漏、不可误杀"的
约束下，把垃圾号挑出来 —— 并且挑出词库挑不到的那些？**

---

## 二、评测集（两侧标签都来自外部人工整理）

| 侧 | 来源 | 规模 | 为什么有资格当 ground truth |
|---|---|---|---|
| **阳性** | `daymade/Twitter-Block-Porn` 公开黄推名单 | 882 条 → 确定性抽样 **80** | 第三方人工整理，与本项目无利益关系 |
| **阴性** | 本机 x.com 登录账号的**关注列表** | **80**（另留 20 备用） | 用户亲手挑的人，定义上就是"绝不能误杀"的总体 |

抽样种子 `SEED=20260919` 固定，任何人可复现同一批 handle。

> **绝不用词库命中来标阳性。** 否则评测退化成"拿自己的输入验证自己的判据"，
> 必然 100% 假成绩 —— 这个坑在 `naslib-pick/SKILL.md` 里已经吃过一次
> （用 CLIP 美观分验证 CLIP 美观分）。

### 标签审计（必须做，且必须如实报告）

名单可能陈旧、账号可能被转手。抽 **20 阳 + 20 阴**，人工复核**当前内容**是否仍符合标签：

- 若阳性集里 **>30%** 已不是垃圾号 → 结论降级为「在**仍然活跃的阳性子集**上」，
  并把该子集规模一并报出。
- 阴性集里若混入明显垃圾号 → 从阴性集剔除并报数。

---

## 三、判定输入（`state`）= 扩展在时间线上真能拿到的东西

只用 XHR 桥 + DOM 能拿到的字段，不许喂扩展拿不到的信息（否则结论无法落地）：

```
账号档案
handle / 昵称 / 简介
粉丝数 / 关注数 / 推文数 / 注册时间 / 有无自定义头像 / 是否蓝标
外链域名
近期推文 N 条（正文 + 外链域名 + 是否带图）
```

**不喂**：名单成员身份、社区票数、关注关系是否指向已知垃圾号（这些要么是答案泄漏，
要么扩展在滚动时拿不到）。

## 四、提问（一次调用内扇出，每账号 3 问）

| 问题 | 类型 | 用途 |
|---|---|---|
| `spam` | **noul** | 主信号（0–1 连续概率） |
| `category` | choice | UI 上的分类徽章（6 选 1） |
| `evidence` | choice | UI 上的"为什么标它"（简介/推文/外链/昵称/行为/无） |

`category` 选项固定为：`adult_gray_traffic`、`scam_phishing`、`bot_spam`、
`engagement_bait`、`legit_person`、`legit_brand`。

---

## 五、判据（跑之前钉死）

### H1 判别力（主判据）

- 账号级 **AUC(spam) ≥ 0.90**
- 且在 **误杀率 FPR ≤ 2%** 的阈值下，**召回率 Recall ≥ 0.60**

> 为什么 FPR 卡 2%：这是"帮你拉黑"的产品。误杀一个真人（写小说的、抱怨黄推的、
> 币圈聊天的）比漏掉一个垃圾号贵得多 —— 本数据集里已经看到 778 条词库把
> `jiangdajishi`（抱怨黄推的人）、`Hrb9si`（小说作者）判成命中。**宁可漏，不可误杀。**

### H2 扇出无损（决定成本模型能不能成立）

- **batch=10** 与 **batch=1** 的判定**一致率 ≥ 0.90**，且 AUC 差 **≤ 0.03**

> 扇出是 Jev 唯一"不像 LLM"的地方（1→20 问延迟只涨 3–11%）。但把 10 个账号塞进
> 一个 `state` 有**串味**风险（#3 的黄推味污染 #7 的判断）。这条判据是专门用来
> 抓这个风险的：**过不了就必须退回小批量，成本结论随之作废。**

### H3 不是背名单（记忆污染探针）

- 把 handle 替换为**同长度、同字符集的随机串**后重跑，**AUC 下降 ≤ 0.05**

> 阳性集来自公开 GitHub 名单，Jev 完全可能在预训练里见过这些 handle。
> 对应 jev 套利项目的 E4b 消毒标题探针。

### H4 增量价值（相对 778 条词库的净增益）

- 在**词库完全未命中**的阳性子集上，**Recall ≥ 0.40**（用 H1 选定的阈值）

> 词库能抓的，Jev 抓到了不算本事 —— 那只是把词库重说一遍。
> 只有词库抓不到的垃圾号被 Jev 抓到，这个产品才值得做。

### H5 成本与延迟

- 单账号判定成本 **≤ $0.0005**（按实测 input_tokens × $0.042/Mtok）
- batch=10 时每账号摊薄延迟 **≤ 0.5s**，p50 单次调用延迟 **≤ 2s**

---

## 六、诚实条款（预先声明会被如实报告的东西）

1. 判据不过就是不过，**不许**事后调阈值、换指标、缩小样本再报。
2. 若 H2 失败（扇出串味），成本结论作废，但仍要报出 batch=1 的成绩。
3. 若标签审计发现阳性集大量失效，按第二节降级口径报告。
4. 阴性集只有 80 个账号，**FPR 的置信区间会很宽**（观察到 1 个误杀时，
   真实 FPR 的 95% 上界约 6%）—— 报告里必须带区间，不许只报点估计。
5. 明确声明本评测**不能**回答的问题：线上 DOM/XHR 取数稳定性、
   时间线里垃圾号的真实占比、以及封号后的对抗演化。

## 七、产出

| 文件 | 内容 |
|---|---|
| `jev/data/positives.jsonl` / `negatives.jsonl` | 两侧档案（可复现） |
| `jev/data/jev_judgments.jsonl` | 每条判定（含 input_tokens / 延迟 / 原始 answers） |
| `jev/RESULTS.md` | 按 H1–H5 逐条给结论 + 选定的上线阈值 |

## 八、选阈值的方式（预先钉死）

上线阈值不取"AUC 最大点"，而取**满足 FPR ≤ 2% 的最低阈值**在阳性集上的召回，
并在 `RESULTS.md` 里同时给出该阈值、覆盖率与错分样本清单（供人工复核）。
